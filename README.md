# RoadVision --- Android 道路视觉感知

RoadVision 是一个面向 Android
手机的本地优先道路视觉感知项目。首阶段交付目标为**内部测试
APK**，在经确认的荣耀真机上验证车辆检测、车道识别、车辆跟踪和车牌 OCR
的端到端可行性。

> **当前状态：立项与技术验证阶段。**
> 本仓库文档中的目标、估算和待验证事项不代表已经实现或实测通过。持续稳定
> 15 FPS 是验收目标，不是当前性能承诺。仓库不包含模型权重；缺少清单时应用只采集不推理，
> 也可以使用车辆-only 清单先验证车辆检测链路。

## 项目决定

-   **项目名：** RoadVision
-   **处理策略：**
    默认在设备本地处理；未来如增加上传能力，必须由用户主动触发、明确告知上传内容与目的，并提供取消/删除机制。
-   **首版功能：** 车辆检测、车道识别、车辆跟踪、车牌检测与
    OCR、事件列表和本地记录。
-   **交付形式：** 内部测试 APK，不作为公开发行版。
-   **性能目标：**
    在明确的荣耀机型、系统版本、测试场景和热状态下，端到端持续稳定达到
    15 FPS。
-   **技术路线：** Kotlin、CameraX、ONNX 模型、ONNX Runtime Android。
-   **商业约束：** 目标为闭源商业用途；所有代码、模型权重、训练数据、SDK
    和依赖必须完成许可证审查后才能进入候选发布构建。

## 首阶段目标

1.  明确测试设备与测试基线。
2.  完成许可证与模型来源审查，建立第三方组件清单。
3.  建立可运行的 Android 工程、CameraX 采集和可观测性。
4.  验证 ONNX Runtime 推理、模型输入输出契约与真机性能。
5.  逐步接入车辆检测、车道识别、跟踪、车牌检测和 OCR。
6.  完成连续运行、温升、功耗、隐私与熄屏行为测试，形成可复核报告。
7.  输出内部测试 APK 和已知问题清单。

## 当前非目标

-   不承诺所有荣耀机型均达到 15 FPS。
-   不做驾驶安全关键系统，不替代驾驶员判断或车辆原厂安全功能。
-   首阶段不做云端自动上传、账号体系、远程车队平台。
-   不承诺仅凭单目视频精确测距或测速。
-   不在许可证未核验的情况下把某个模型权重用于闭源商业发布。

## 技术结构

``` text
CameraX
  └─ FrameScheduler（限流、旋转/裁剪、背压）
      ├─ VehicleDetector (ONNX)
      ├─ LaneDetector (ONNX)
      ├─ PlateDetector (ONNX)
      └─ PlateRecognizer (OCR ONNX / 可替换实现)
            ↓
       VehicleTracker
            ↓
       ResultFusion / PlateVehicleMatcher
            ↓
       UI Overlay + Event List
            ↓
       Room local storage
```

推理接口应与具体模型解耦。CPU/XNNPACK 作为首个基线；NNAPI
或设备专用执行提供器只有在目标机型上通过兼容性和性能实测后才可启用。

## 开发原则

-   先验证许可证，再锁定模型。
-   先建立基准测试，再讨论性能优化。
-   以最新帧优先，避免推理队列积压。
-   所有模型输出先经过契约验证和置信度/坐标后处理。
-   UI 与推理解耦；不得在主线程执行模型推理。
-   默认本地处理；不得在未明确授权时上传视频、帧、车牌或识别结果。
-   每项性能和准确率结论都必须标明是目标、估算还是实测。

## 建议开发环境

-   Android Studio / 对应稳定版 Android Gradle
    Plugin（具体版本在工程初始化时锁定）
-   Kotlin
-   CameraX
-   Jetpack Compose 或传统自定义 View（UI
    技术需在工程骨架任务中最终确定）
-   ONNX Runtime Android
-   Room、Coroutines/Flow
-   Git 与自动化构建

具体版本必须在实现时锁定并记录；不得在未验证的情况下把"最新版本"写成兼容性事实。

## 许可提示

ONNX
格式本身不代表模型可自由商用。必须分别审查模型代码、权重、训练数据、预处理/后处理代码、OCR
字库和每个第三方依赖。Ultralytics 相关代码或权重若采用其 AGPL-3.0
路线，可能与闭源分发目标产生冲突；在取得合适授权或完成法务审查前，不得纳入候选发布构建。导出为
ONNX 不会自动消除上游许可证义务。
