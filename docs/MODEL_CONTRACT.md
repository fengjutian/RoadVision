# RoadVision 模型输入输出契约

## 1. 总则

所有模型都必须提交模型卡、输入输出说明、预处理和后处理说明、来源、许可证、版本与
SHA-256。未填写的契约不能进入集成测试。

## 2. 通用输入契约

-   输入布局：明确 NCHW 或 NHWC。
-   数据类型：明确 FP32 / FP16 / INT8 等。
-   输入尺寸：明确宽高和动态维度。
-   颜色顺序：RGB 或 BGR。
-   数值范围与归一化：明确是否 `[0,1]`、均值/标准差。
-   缩放/letterbox：明确算法与 padding 处理。
-   旋转/裁剪：记录原始帧到模型输入的变换。
-   运行时版本与执行提供器：写入测试记录。

## 3. 车辆检测模型

必须明确： - 输出张量名称、形状、数据类型 - 类别 ID 与标签映射 -
置信度定义 - NMS 是否由模型内部完成 - 坐标单位与映射方式 - 阈值、NMS IoU
和最大候选数

上述阈值、NMS IoU 和最大候选数写入 `model-bundle.json` 的 `vehicle.decode` /
`plate.decode` 块（`confidence`、`nmsIou`、`maxDetections`）；车道阈值写入
`lane.decode.threshold`。未填写时使用代码默认值，但发布前必须与模型卡一致。

## 4. 车道识别模型

必须明确输出属于： - 车道线关键点/坐标，或 - 分割掩码，或 -
其他特定结构。

必须定义输出坐标如何映射回原始预览画面，以及无效/低置信度结果的处理规则。

## 5. 车牌检测与 OCR

车牌检测模型和 OCR 模型分别定义输入输出： - 车牌框坐标、置信度、类别 -
裁剪顺序、矫正方式和最小尺寸 - OCR 字符集、空白/分隔符规范化规则 -
字符级或整牌置信度的来源 - 是否支持目标市场的车牌格式 -
低质量图像的拒识规则

不得把通用车辆检测模型描述为能够直接输出车牌字符，除非具体模型的输出契约明确包含该能力并通过测试。

## 6. 一致性测试

-   固定一组合法测试图像。
-   保存参考运行时输出和 Android 输出。
-   对坐标、置信度和 OCR 结果设定容差。
-   检查 NaN/Inf、空输出、极端坐标、异常张量形状。
-   每次替换模型或预处理流程后重新执行。
