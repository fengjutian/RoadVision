# RoadVision 首阶段任务拆分

## 工作规则

-   先做许可证审查与真机基线，不先投入大规模模型集成。
-   每个任务必须有负责人、代码/文档产物、验收条件和状态。
-   任务状态初始均为"待开始"；本文件不表示任务已完成。
-   任何模型替换都要更新模型契约、许可证清单和基准数据。

## 建议执行顺序

**P0 → P1 → P2 → P3 → P4 → P5 → P6**。P0 与 P1
可以在不引入未审查模型的前提下部分并行。P2
需要尽早使用目标荣耀真机。若车辆单模型的耗时已接近或超过 66.7 ms（15 FPS
的帧预算），应在继续堆叠完整流水线前先调整模型、输入尺寸或调度策略。

## 首阶段完成定义（DoD）

-   工程可重复构建。
-   许可证审查没有未解决的闭源分发阻断项。
-   车辆检测、车道、跟踪、车牌 OCR 具备端到端演示。
-   本地事件记录、删除和日志脱敏通过检查。
-   有明确设备条件下的持续 FPS、延迟、热状态、内存和耗电报告。
-   若达到 15
    FPS，报告可复现地证明；若未达到，报告明确标注失败与下一步措施。
-   内部 APK、源代码版本、模型 hash、依赖清单和测试报告一一对应。
