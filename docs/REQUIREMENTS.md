# RoadVision 需求范围与验收标准

## 1. 用户与使用场景

首阶段面向开发团队内部测试人员，用于验证手机端道路视频感知能力。测试人员在合法、安全、固定的测试环境中启动采集，查看实时叠加结果和识别事件。

不得要求驾驶员在车辆行驶时手动操作手机；测试应由乘客、固定安装设备或封闭/安全测试场景执行。

## 2. 功能需求

### FR-01：摄像头采集

-   使用 CameraX 获取预览帧。
-   处理旋转方向、裁剪区域、输入尺寸和帧时间戳。
-   采用有界缓冲或最新帧策略，防止推理队列积压。
-   所有 `ImageProxy` 必须在处理结束后关闭。
-   相机权限被拒绝、摄像头不可用或生命周期结束时，界面应给出明确状态。

**验收：** 连续运行 30
分钟无因帧未关闭造成的持续性卡死；日志可统计采集帧、处理帧和丢弃帧。

### FR-02：车辆检测

-   在道路画面中检测目标车辆。
-   显示边界框、类别和置信度（可配置是否显示置信度）。
-   阈值、输入尺寸和类别映射通过配置管理。
-   模型输出必须经过形状、坐标范围、NaN/Inf 检查。

**验收：** 使用固定测试样本集记录检测召回率/精确率或
mAP；阈值与测试集版本写入报告。数值门槛在取得合法测试集和首轮基准后冻结。

### FR-03：车道识别

-   输出车道线/车道边界的可绘制表示。
-   对无车道线、逆光、夜间和遮挡情况允许输出"低置信/不可用"，不得伪造稳定车道线。
-   车道结果应包含时间戳和置信度或质量指标。

**验收：** 在标注样本集上记录车道偏差、有效检测率和失败场景；指标门槛由
M2 后冻结。

### FR-04：车辆跟踪

-   为持续出现的车辆分配临时 Track ID。
-   遮挡、出画和重新进入时允许 ID 变化；不得承诺跨长时段身份识别。
-   跟踪输入必须带时间戳；检测帧率波动时仍应使用真实时间差。

**验收：** 在固定视频上记录 ID
切换、漏跟踪和跟踪稳定性；测试视频和配置可复现。

### FR-05：车牌检测与 OCR

-   检测车牌区域，并在可行时进行裁剪、旋转矫正和 OCR。
-   OCR 以按需触发为原则，不默认每帧执行完整 OCR。
-   对同一 Track ID 的多个 OCR 结果进行多帧融合。
-   显示识别文本、置信度、时间；低置信度结果必须标记不确定。
-   支持隐藏/删除车牌文本；默认日志不记录完整车牌。

**验收：**
记录车牌检测召回率、字符级准确率/整牌准确率、低置信度比例和与车辆 Track
ID 的关联错误率。指标阈值需在合法标注数据集上建立基线后冻结。

### FR-06：结果融合

-   将检测、车道、跟踪、OCR 结果按时间戳关联。
-   车牌与车辆关联使用几何关系、时间连续性及多帧证据；不得仅以单帧位置关系认定高置信关联。
-   过期结果不能覆盖新结果。

**验收：** 在测试集上记录错配率；日志可还原融合前后的时间戳和 Track
ID（车牌内容脱敏）。

### FR-07：UI 与事件列表

-   实时视频画面上绘制车辆框、Track ID 和车道线。
-   侧边/下方列表显示车牌裁剪图（如启用）、识别文本、置信度和时间。
-   明确显示相机状态、推理状态、FPS 和错误状态。
-   UI 更新与推理线程解耦。

**验收：** 旋转、暂停/恢复、权限失败和推理异常情况下界面不崩溃；FPS
指标来源可追溯。

### FR-08：本地记录

-   本地存储事件元数据，使用 Room 或同等本地数据库。
-   用户可以删除单条或全部本地事件。
-   设置合理保留策略；首阶段默认不上传。
-   数据库 schema 版本化。

**验收：**
重启后记录按保留策略存在；删除后列表和本地存储均反映删除结果。

### FR-09：诊断与性能

-   记录采集 FPS、有效推理 FPS、端到端延迟
    P50/P95、丢帧率、内存、温度/热状态（可获取时）、异常计数。
-   日志不得默认包含完整车牌、原始视频帧或敏感路径。
-   性能指标在固定时间窗口内统计。

**验收：** 导出一份带设备与构建元数据的测试报告；可从日志复算主要指标。

## 3. 非功能需求

-   **性能：** 目标设备上持续稳定 15 FPS；必须通过真机实测确认。
-   **可靠性：** 处理队列有界；相机资源和推理 Session 正确释放。
-   **隐私：**
    默认本地处理，网络上传关闭；未来上传必须由用户主动触发并显示内容/目的/接收方。
-   **可维护性：** 模型适配层可替换；模型和依赖有版本与 hash。
-   **兼容性：**
    首阶段仅对选定荣耀机型与系统版本验收，不泛化为全机型支持。
-   **商业许可：** 未完成许可证审查的模型/依赖不得进入候选发布 APK。
-   **安全性：**
    该系统仅作为感知与研究工具，不作为驾驶安全关键决策依据。

## 4. 性能口径

建议将"15
FPS"定义为**有效端到端感知输出帧率**，而不是相机预览帧率。报告需同时列出： -
CameraX 采集帧率； - 车辆检测完成帧率； - 车道结果更新率； -
完整融合结果更新率； - 车牌 OCR 触发频率； - 端到端延迟 P50/P95； -
被丢弃/跳过帧比例。

**建议首轮验收窗口（项目建议，待团队确认）：** - 连续 30
分钟稳定性验收； - 60--120 分钟扩展测试； -
同时记录设备温控状态与电量变化。
该窗口是测试设计建议，不是现有实测结果。

## 6. 暂缓需求

-   精确车速、车距和地理定位。
-   交通事故自动判责。
-   云端账户、视频云存储和自动上传。
-   多机型广泛适配承诺。
-   驾驶辅助或安全关键报警。
-   未完成合法性审查的数据采集或模型训练。
